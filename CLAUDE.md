# Bitcade

A GitHub Pages arcade site: a lobby page plus 32 classic-style browser games. Plain HTML, CSS and canvas JavaScript. No build step, no frameworks. The only outside dependencies are Google Fonts and the Firebase SDK, loaded from gstatic only for the world leaderboard.

## Layout

- `index.html`: the lobby. The `GAMES` array lists each cabinet: slug, `genre` (space-separated ids from `GENRES` in `shared/shelves.js`: shooter, racing, puzzle, action, platform, adventure, sports, strategy, fighting, rhythm, 2p), `added` (the date it joined, for New arrivals and the NEW tag), name, colour, blurb, and a 12×8 pixel icon with two frames (`px`, `px2`) that alternate. Cabinet screens show two frames of real footage over the icon, `icons/screens/<slug>-1.webp` and `-2.webp`, made by `node tools/make-screens.mjs [slug ...]` from each game's attract demo (re-run it after changing how a game looks; the tests check every game has them). The walkable floor still uses the pixel icons. Add a new game here to show it in the lobby. The lobby opens with a boot sequence that plays once per visit (`sessionStorage` `bitcade:booted`) and replays with `?boot`: a power switch waits for the first key, tap or controller button (which also unlocks sound), then a CRT power-on, the BIOS check, a flight over the neon grid between rows of cabinets, and the logo landing with lightning. At INSERT COIN a press drops a coin in the slot, the doors slam shut, their BITCADE sign lights letter by letter and they slide open on the lobby. A press skips the BIOS to the flight, lands the logo early, or hurries the coin and doors. Reduced motion skips the switch and the show. After a minute idle (`?idle=5` shortens it for testing), attract mode brings the title back, alternating with a high-score screen built from the cabinets. The lobby plays the Bitcade theme and has a ♪ MUSIC button. A view bar switches between the cabinets grid, WALK THE ARCADE (remembered in `bitcade:view`) and ★ PROFILE (`?view=profile` opens it), and opens the prize counter.
- `shared/arcade.css`: the cabinet frame shared by every game page (header bar, screen, overlay, touch pad).
- `shared/arcade.js`: the shared kit, exposed as `window.Arcade`. It covers:
  - high scores in localStorage: `arcade:best:<slug>` (the record), `arcade:top:<slug>` (top 10 with initials, JSON), `arcade:daily:<slug>` (today's daily-challenge best)
  - `A.submit(score, daily)` on game over. The next `A.overlay` call then asks for initials if the score made the top 10, and shows the table
  - world leaderboard: saving initials queues the score in `arcade:outbox` and posts it through `shared/world.js` (Firebase project `bitcade-4fa25`, Firestore Lite plus anonymous auth, loaded on demand). Score tables have WORLD and THIS DEVICE tabs. Every page must keep working when Firebase is unreachable
  - daily challenges: `A.seeded(key)` returns a seeded random function, and `A.today()` returns the local date. Stackdown, Wallbuster, Twin Blast, Mole Patrol and Wing Duel use them (only for layouts, never for enemy moves), with a Daily button on the title screen. A new daily game also needs its slug in the daily rule in `firestore.rules`. A run that beats the player's best today goes to that day's world board (`daily/{game}/days/{YYYY-MM-DD}/scores`) along with the all-time board, in one write. Pass `daily: true` to `A.overlay` to add a TODAY tab
  - weekly tournament: `window.WEEKLY` (at the end of `shared/badges.js`) picks one featured game per week (Monday to Monday, UTC) from its `ROTATION` list, starting with the week of 2026-10-12 (`FIRST`); add new score games at the END of the list, so the current week's game never changes when a game is added. `A.featured()` and `A.week()` tell a page whether it's featured and the week's id (its Monday). On the featured game the title screen shows a ★ WEEKLY TOURNAMENT banner, score tables get a THIS WEEK tab, and a run that beats the player's best this week (`arcade:week:<slug>`) also goes to `weekly/{game}/weeks/{monday}/scores` in the same write. The lobby shows a banner with the countdown and world top 3, and a ribbon on the cabinet. `?feature=<slug>` (or `none`) overrides the pick for testing; the smoke tests use `none` unless they pick one
  - badges: `A.badge(id)` unlocks one (toast and jingle, once). Definitions for every game live in `shared/badges.js`, loaded before arcade.js and by the lobby. Score tables get a BADGES tab
  - a Share score link on game-over screens (share sheet, or copy to the clipboard)
  - sound (`tone`, `noise`, `jingle`, and presets via `A.sfx('pickup' | 'powerup' | 'hurt' | 'boom' | 'laser' | 'jump' | 'select')`). Effects run through one bus with a compressor and a short cabinet echo; long noises are filtered explosions with a bass thump, and every `A.shake` of 5+ adds bass. Starting a run from a title or game-over screen plays a coin drop (`A.coin`)
  - MUSIC and CRT header toggles (`arcade:music`, `arcade:crt`). Music is on by default: each game's theme from `shared/chip.js` plays from the title screen right through the game (quieter during play) until MUSIC is turned off
  - CRT: the button cycles LITE (the default, `body.crt-lite`: faint scanlines and glow), FULL (`body.crt`: strong scanlines, vignette, flicker) and OFF. `arcade:crt` stores 'lite', '1' or '0'
  - keyboard, touch and gamepad input (`held`, `onPress`, `swipe`, `[data-k]` pad buttons). Inside an element marked `data-keys-native`, keys are left to the page
  - a header PAUSE button for touch, added automatically unless the pad already has a `KeyP` button
  - canvas sizing
  - the cabinet: `buildCabinet()` wraps `.screen` in a lit marquee (the page's h1), a bezel with the 1UP / HI-SCORE / FREE PLAY strip (it moves `.sc` there) and a control panel (joystick, the `.help` card, buttons). Phones and narrow windows get a slim version and keep the touch pad. Screen size comes from `--cab-chrome` in arcade.css (measured heights of everything around the screen) on wide windows. On phones and narrow windows `fitScreen()` measures the header, marquee, score strip and that game's touch pad and sets `--sw` so the screen fills what's left and nothing spills off the bottom; the frame is slimmer there and the header stays one row. A phone held sideways gets `body.phone-land`: no marquee, and the pad's two halves (`.pad > *`) sit either side of the screen
  - the fixed-step `loop`
  - game feel, drawn by the loop on top of the game: `A.shake(px, s)`, `A.hitstop(s)`, `A.burst(x, y, { n, color | colors, speed, life, size, gravity, angle, spread, kind: 'spark' | 'debris' | 'smoke' })`, `A.pop(x, y, text, colour)`, `A.ring(x, y, colour, r)` and `A.flash(colour, s)`. Every game uses them for its big moments (hits, kills, deaths, clears). Reduced-motion players get no shake
  - easy mode: the EASY header button (`arcade:easy`, `A.easy`) runs games at 70% speed, and games with lives start with 5 (`lives = A.easy ? 5 : 3`). A run that had easy mode on at any point counts for nothing: no score, top 10, daily or weekly board, world post, badge or tickets, and game over says SCORE NOT RECORDED. Nothing easy is ever sent to Firebase, so the rules need nothing for it
  - attract demos: each kit game calls `A.attract({ start, stop, bot })` just before its title overlay. After 12 s on the title screen (`?demo=2` shortens it) the game plays itself for 30 s with a DEMO banner: `bot(dt)` returns the key codes to hold (`'!Code'` taps one), sound is silent, and nothing is scored. Any key, tap or controller input ends it; so does the game reaching a pause or game-over screen. `stop()` must put the game back in its title state. Game-over screens drift back to the title after CONTINUE? runs out
  - screen transitions: the lobby drops a coin and powers off like a CRT (the picture collapses to a line) when a cabinet is picked, setting `bitcade:enter` in sessionStorage; the next page powers on (a line of light opens out). Game back links (`a[href="../../"]`) power off the same way via `A.crtOff(href)`. Reduced motion gets a plain fade
  - mastered cabinets: with every badge for a game earned, `body.mastered` gives that cabinet a gold marquee with a light sweep, gold side stripes and a ★ MASTERED ★ plaque in the score strip (a toast and fanfare announce it). The lobby grid, the walkable floor and the profile trophy case show mastered cabinets in gold too
  - title logos: on title screens the overlay draws the game's name as an animated logo (block, neon, chrome, pixel or retro style, set per game in `LOGOS` in arcade.js; the name stays in the h2 for screen readers), over a lighter backdrop so the game's own title scene shows through
  - the start/pause/game-over `overlay`. Pass `scores: true` on title screens to list the top 10 (they also show PUSH START and FREE PLAY · CREDIT 99), and `alt: { btn, onGo }` for a second button (gamepad Y) and `alt2` for a third (gamepad X). After `A.submit`, game over shows a CONTINUE? 9→0 countdown, and tables rank 1ST/2ND/3RD in gold, silver and bronze
- `shared/shelves.js` (lobby only): the cabinets page, `window.Shelves`. It opens on shelves, sideways rows of small tiles: Continue playing (`bitcade:recent`, which `A.submit` keeps, then anything else played, by play time), ★ Favorites, New arrivals, Not tried yet, Daily challenges and one per genre with two or more games. SEE ALL, a genre chip, the search box (`/` jumps to it) or the sort (featured, A–Z, newest, most played, not tried first) shows the grid (`#floor`, the `.cab` cards) filtered and sorted; ‹ SHELVES goes back. The search, chip and sort last for the visit (`bitcade:cabs` in sessionStorage). A ★ on any cabinet or tile pins it (`bitcade:favs`, per device). ▣ / ▦ switches big and small cabinets (`bitcade:cabsize`; small by default on phones, two or three across).
- `shared/boot.js` (lobby only): `window.Boot`, the boot's canvas flight (`Boot.flight(canvas)`, drawing cabinets from `Boot.games`, which the lobby sets) and its own sound effects (`Boot.sound`: power, hum, disk, swell, whoosh, slam, coin, doors and so on; silent with SOUND off). The lobby theme starts once the doors open.
- `shared/floor.js` (lobby only): the walkable arcade floor, `window.Floor`. A big, dark, neon-lit arcade (2880×1320 world units) that scrolls with a following camera (closer in on phones), with a minimap you can tap. Its areas: the Raceway (sit-down racers for Turbo Tour, Nitro Lane, Light Trail), the main floor (two rows of uprights), the Shooting Gallery (light-gun cabinets for Raptor Ridge and Marsh Marksman), the Lounge (Blip Sports on a coffee table, sofa, beanbags, snack bar, jukebox, pinball machines), the entrance (high-score wall, photo booth, benches) and the Prize Corner (prize counter, Mega Claw, skee-ball). Neon Steps is a dance machine (with a pad you stand on) by the entrance, next to the newest uprights; other games fill the main floor, then the slots by the entrance and below the raceway. East of the gallery and prize corner, behind a velvet rope and a bouncer, is the VIP room (`window.VIP` in `shared/badges.js`: it opens for good, in `bitcade:vip`, at 30 badges, 3 mastered cabinets or 1,500 tickets earned; `?vip=1` opens it for testing). Inside: the Hall of Masters (a gold cabinet for each mastered game, laid out on every start), the VIP prize counter, your records wall, the golden soda bar, velvet sofas and three VIP regulars who never leave. Prizes with `vip: true` in prizes.js (Platinum Cabinet, Tuxedo, Golden Suit, Royal Velvet) can only be bought once it's open. Cabinets light the floor in their colours (a light map over the room) and play their `icons/screens` footage. Ten arcade-goers wander, play cabinets, pinball and skee-ball, sit, get sodas, crowd the tournament cabinet, greet you and talk about real scores. Walk with arrows/WASD, a controller, or tap (A* pathfinding round everything); hold Shift or B to run. Enter or PLAY at a cabinet steps you up (into the seat on a racer) and the camera dives into the screen before the CRT switch. It draws the outfit, carpet and decorations from the prize counter. `Floor.state()` and `Floor.goTo(slug | 'counter' | 'claw' | 'jukebox' | 'board' | 'booth' | 'snack' | 'skee' | 'pinball' | 'hockey' | 'golf' | 'vipdoor' | 'vipcounter' | 'records' | 'vipbar' | [x, y])` are there for tests.
- `shared/floor-play.js` (lobby only, loaded before floor.js): `window.FloorPlay(kit)`, the floor's attractions and sound. The jukebox picks the lobby's tune (any game's theme, kept in `bitcade:jukebox`); the high-score wall lists world records and your bests; the photo booth takes a four-shot strip you can save as a PNG; the Mega Claw gives three free goes a day (`bitcade:claw`; four with the Claw Machine prize) for 2 to 50 tickets; the snack bar hands you a soda; the skee-ball lanes (aim, hold to charge, let go to roll; nine balls) and the four pinball machines (a small physics table: plunger, flippers, bumpers, slingshots, rollover lanes; three balls) are playable, keep bests in `bitcade:skee:best` and `bitcade:pinball:best`, and pay a ticket per 100 and per 4,000 points. Air hockey (you against the house, first to 7, 3 tickets a win, `bitcade:hockey:wins`) and mini-golf (six holes in `HOLES`, par 17; drag back and let go or hold Enter; tickets for going under par, best in `bitcade:golf:best`) are on the floor too. All of these share a cap of 30 tickets a day (`bitcade:floortix`). Sounds: crowd murmur, cabinets bleeping in stereo as you pass, footsteps, a jingle when a cabinet notices you, cheers. The Jukebox and Claw Machine prizes upgrade those machines.
- `shared/profile.js` (lobby only): the profile view, `window.Profile`: a player card (initials you can edit, a rank from badges, totals including play time from `arcade:time:<slug>`), the cloud save panel, a trophy case per cabinet with its badges, and the prizes collected.
- `shared/save.js` (ES module, loaded on demand by the lobby and by arcade.js after each game over): cloud save. Turning it on makes a sync code (`bitcade:sync`, like K7QM-2XRT-9BHF); typing it on another device joins the same save at `saves/{sha256}` in Firestore. Each sync pulls, merges and pushes: bests and counters take the higher value (they add up when a device first joins), top 10s combine, badges and prizes union, tickets spent are recomputed from the prizes owned. `arcade:outbox` and the settings (muted, music, crt, easy, equip) stay per device. Tickets are kept as `arcade:tickets:earned` and `arcade:tickets:spent` so this works.
- `shared/prizes.js` (lobby only): the prize counter, `window.Prizes`. It spends tickets on screen tints and cabinet finishes (body classes `tint-<id>` and `skin-<id>` that arcade.js adds on every game page, styled in arcade.css), and outfits, carpets and decorations for the floor. `arcade:prizes` lists what's bought, `arcade:equip` what's worn per slot.
- daily missions: `window.MISSIONS` at the end of `shared/badges.js`. Three a day (the same for everyone, seeded by the local date): a score in one game (`TARGETS`, about two to three times the demo bot's 15-second score; a new score game needs one), a kind of play (different games, an area, the tournament, a daily challenge) and something on the arcade floor (skee-ball, pinball, the claw, the photo booth, a Blip Sports win). 10 tickets each, 20 more for all three. `A.submit` reports `{ type: 'run' }` through `A.mission`, which toasts finished missions; the floor and Blip Sports report their own events. The lobby shows them as cards (tap one to go and do it). Kept per device in `bitcade:missions`; easy runs and demos don't count
- player level: `window.XP` at the end of `shared/badges.js`. `arcade:xp` is lifetime XP (cloud save sums it on joining, else keeps the higher; first visit back-pays 12 per game played and 50 per badge). Level n needs 50 + 20n more XP, up to 50. XP comes from `A.gainXP(n)` in arcade.js: a scoring run 10 (+10 top 10, +15 record, +5 daily, doubled on the tournament game), a badge 50, a mission 30 (+50 for all three), a Blip Sports win 20; floor games give 8 and floor missions their share through floor-play.js. Never in easy mode or demos. Levels bring titles (`TITLES`), a nameplate over you on the floor from level 3, and free prizes (`REWARDS`, prizes.js items with a `level`, added to `arcade:prizes` when reached: Varsity Jacket, Starfield, Skater, Race Track, Space Captain, Synthwave Sunset, Aurora, Bitcade Legend). Game over shows +XP and an XP bar; level-ups get a toast and fanfare. The lobby shows a level strip with the next reward, and the profile card the level and title
- tickets: `window.TICKETS` at the end of `shared/badges.js` (balance in `arcade:tickets`). `A.submit` pays 1 per scoring game, +3 for the top 10, +2 for a new #1, +5 for beating an earlier record and +2 for a daily run, doubled on the weekly tournament game, and shows it on game over; each badge pays 10 and each Blip Sports win 5. New players start with 20 plus back pay for badges and games already played.
- `shared/chip.js`: the chiptune player (`window.Chip`), loaded before arcade.js on kit games and by the lobby. `Chip.lobby` is the hand-written Bitcade theme; `Chip.theme(slug)` composes a game's theme from its name (same tune every time). Music needs a tap or key first (browser rule) and plays only with SOUND and MUSIC on.
- `games/<slug>/index.html`: one self-contained page per game, loading the shared kit with `../../shared/`.
  - `body data-game="<slug>"` sets the score key.
  - `style="--game:#hex"` sets the accent colour.
  - `data-pad="0:KeyK 2:KeyJ"` maps gamepad buttons (standard mapping index) to key codes. The defaults are d-pad and left stick → arrows, A (0) → Space, Start (9) → KeyP. A or Start also presses the overlay button.
  - `data-sticks="wasd arrows"` makes the left stick press WASD and the right stick the arrows (Twin Blast's twin-stick controls). The default is the left stick as arrows.
- `games/blip-sports/`: the exception. It's an LED handheld (football and baseball) with its own shell and styles, not the kit's overlay or arcade.css. It does load arcade.js for keys, gamepad, badges and the world wins board (`A.postWin`, `wins/{uid}` in Firestore). Its own pause freezes game time. It tracks local wins in `arcade:best:blip-sports`. On phones the handheld is compact enough to fit the screen, scrolls back into view when a game starts (the setup is below it), and held sideways puts the d-pad and buttons either side of the LED screen.

## Games

neon-noodle (snake), wallbuster (brick breaker), star-siege (alien shooter), rock-rift (asteroids), stackdown (falling blocks), back-alley-brawl (1v1 fighter vs CPU ladder), circuit-chase (maze chase), highrise-handyman (fix-it climber), nitro-lane (racing), volley-duel (paddle duel, 1P vs CPU ladder or 2P on one keyboard/tablet), crater-lander (lunar lander), sky-shield (missile defense), hedge-hop (road crossing), scaffold-scramble (girder climber), swarm-strike (dive-bomb shooter), garden-gunner (caterpillar shooter), cube-hopper (pyramid hopper), light-trail (light-cycle duel, 1P vs CPU ladder or 2P), wing-duel (flying joust, 1P waves or 2P duel), twin-blast (twin-stick arena shooter), mole-patrol (dig and trap), turbo-tour (pseudo-3D road racer, world-tour stages against the clock), raptor-ridge (on-rails dino shooter: aim with mouse, touch or keys), marsh-marksman (bird hunt: aim and shoot, rounds of ten), pixel-peaks (side-scrolling platformer, seeded levels), pop-lagoon (bubble shooter), neon-steps (rhythm game: its own synth and seeded songs, three difficulties; on the arcade floor it is a dance machine), blast-brigade (side-scrolling run and gun: hostages give weapons, a tank boss per stage), dungeon-delve (top-down sword adventure: seeded 4×4 room floors, sealed rooms, big key, guardian), lucky-line (fishing: cast, hook, reel against line tension; a lasting fish log in `bitcade:fishlog`), rampart-rush (tower defense: four towers with three levels, endless waves), blip-sports (LED football + baseball).

All names, characters and art are original. Keep it that way: no trademarked game names, characters or sprites.

- `sw.js`, `manifest.json`, `icons/`: the installable, offline app. The service worker precaches the lobby and every game. Site files are network-first and revalidated with the server, so they're fresh when online; fonts and the Firebase SDK are cache-first. Every page links the manifest in its `<head>`. `node tools/make-icons.mjs` redraws the icons.
- `firestore.rules`: the Firestore security rules. They're published by pasting them into the Firebase console (Firestore Database → Rules), not deployed from the repo. A new game needs its slug and a max score added to `maxScore()` there before world scores for it will save.

## Adding a game

1. `games/<slug>/index.html`, using the kit (copy the head tags, including the manifest and icon links, and the chip.js / badges.js / arcade.js script tags from another game).
2. A cabinet in the lobby's `GAMES` array (with its `genre` and `added` date), and the count word in its tagline ("THIRTY-TWO CLASSIC-STYLE GAMES").
3. The slug in `sw.js` `GAMES`, then bump `VERSION`.
4. Its badges in `shared/badges.js`, with matching `A.badge('id')` calls in the game.
   Score games also go in `WEEKLY` `ROTATION` at the end of that file (the tests check it).
5. The slug and a max score in `firestore.rules` `maxScore()`, then publish the rules in the Firebase console.
6. `npm test`. It fails if the lobby, `sw.js`, the manifest links or the badges miss the new folder.

## Conventions

- Every game works on keyboard and touch. Every game also works on a gamepad. Touch pads appear only on coarse pointers.
- Pages need `[hidden]{display:none!important}` (it's in arcade.css), because the overlay uses `display:flex`.
- No text selection, long-press copy menu or double-tap zoom on game pages (`user-select:none`, `-webkit-touch-callout:none`, `touch-action:manipulation` on body, in arcade.css and Blip Sports). Inputs stay selectable.
- Every game is drawn in one house style: a dark outline (`#0a0612`) round every sprite, then fills shaded and lit from above (a `shade(hex, k)` helper in each game), then details; static backdrops are drawn once to an offscreen canvas; pixel-art sprites (Star Siege, Swarm Strike) are outlined and shaded once and cached. Keep that style for new games and characters.
- A new kit game needs an `A.attract` demo bot (the tests check) and `A.easy` extra lives if it has lives.
- Initialise arrays used by draw/update at declaration. The loop runs on the title screen before a game starts.
- Play locally by running `python3 -m http.server` in the repo root and opening http://localhost:8000. Pick another port, such as 5173, if 8000 is blocked, which it is on Windows here.
- Run the smoke tests with `npm install` then `npm test`. `tests/smoke.mjs` serves the repo and opens the lobby and every game in headless Chromium. It checks cabinets and folders match, start, pause and resume, that the canvas draws, the top-10 table, the phone layout, and that there are no errors. New games are picked up automatically from `games/`. Locally it uses installed Chrome or Edge. `package.json` is dev tooling only; the site still has no dependencies.

## Deploy

`.github/workflows/site.yml` runs the smoke tests on every push and pull request. On `main`, a passing run publishes `index.html`, `sw.js`, `manifest.json`, `icons/`, `shared/` and `games/` to GitHub Pages (add any new top-level site file to the copy step in the workflow), so a broken game never goes live. This needs the repo's Settings → Pages → Source set to "GitHub Actions". The site lives at https://gfrazier620-afk.github.io/Bitcade/
